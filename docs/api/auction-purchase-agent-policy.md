## 1. 경매

### 1.1 상태 전이

| 현재 상태 | 다음 상태 | 처리 조건 |
| --- | --- | --- |
| `SCHEDULED` | `LIVE` | 시작 시각에 스케줄러가 처리 |
| `LIVE` | `ENDED` | 종료 시각에 스케줄러가 처리 |
| `SCHEDULED` | `CANCELED` | 시작 전 취소 |

경매 취소는 **`SCHEDULED → CANCELED`에서만** 가능합니다.

### 1.2 등록 · 관리

| 항목 | 정책 |
| --- | --- |
| 시작 시각 | 현재 시각보다 미래여야 함 |
| 진행 시간 | 최소 2분 (`endAt - startAt` 기준, 긴 경매도 가능) |
| 입찰 단위 | **5,000원 고정**. 판매자가 지정할 수 없음 |
| 취소 가능 시점 | 시작 전(`now < startAt`)까지 |
| 시작가 수정 | 시작 1시간 전까지 |
| 상품별 경매 등록 횟수 | **최초 등록을 포함해 총 2회**. 취소한 경매도 횟수에 포함 |
| 동시 등록 제한 | 상품당 예약 또는 진행 중인 경매는 1건만 허용. DB 유니크 제약으로 보장 |

> 총 2회는 **최초 등록 1회 + 추가 등록 최대 1회**를 의미합니다.

### 1.3 재경매

| 이전 경매 결과 | 재경매 |
| --- | --- |
| 유찰: 종료됐으며 입찰 0건 | 가능 |
| 시작 전 취소 | 가능 |
| 낙찰 발생 | **결제 결과와 무관하게 불가** |

재경매에도 상품별 총 등록 횟수 제한을 적용합니다.

### 1.4 직접 입찰

**검증 순서**는 다음과 같습니다.

| 순서 | 검증 | 거절 조건 |
| --- | --- | --- |
| 1 | 사용자 제재 | 입찰 제한 중인 사용자 |
| 2 | 구매 에이전트 관리 여부 | 본인의 에이전트가 관리 중인 경매에 직접 입찰 |
| 3 | 실제 마감 시각 | 마감 시각 경과. 상태가 아직 `LIVE`여도 거절 |
| 4 | 경매 상태 · 참여자 | 시작 전 경매, 종료된 경매, 판매자 본인, 이미 현재 최고입찰자인 사용자 |
| 5 | 입찰 금액 | 현재가 + 5,000원 미만이거나, 현재가 대비 증가분이 5,000원의 배수가 아님 |

입찰 금액 조건은 다음과 같습니다.

```text
입찰 금액 ≥ 현재가 + 5,000원
입찰 금액 - 현재가 = 5,000원 × 양의 정수
```

직접 입찰이 성공하면 다음 동작이 함께 적용됩니다.

- 본인의 해당 경매 자동입찰이 `ACTIVE` 또는 `CAP_REACHED`이면 자동으로 취소합니다.
- `RESERVED` 자동입찰은 취소하지 않습니다.
- 같은 요청이 두 번 들어와도 **한 번만 처리**합니다(`Idempotency-Key`).

### 1.5 종료 연장

| 항목 | 정책 |
| --- | --- |
| 연장 조건 | 마감 전, 종료까지 남은 시간이 10초 이하일 때 사용자 요청으로 실제 입찰 발생 |
| 연장 시간 | 기존 `endAt`에 **20초** 추가 |
| 최대 연장 횟수 | **1회** |
| 연장 제외 | 자동입찰끼리 서로 가격을 올리는 응찰 |

## 2. 자동입찰 · Proxy

### 2.1 상태

기본 전이는 `RESERVED → ACTIVE ↔ CAP_REACHED`이며, 각 상태에서 `CANCELED`로 전환할 수 있습니다.

| 상태 | 의미 |
| --- | --- |
| `RESERVED` | 경매 시작 전에 등록한 자동입찰 |
| `ACTIVE` | 활성 자동입찰 |
| `CAP_REACHED` | 상한 도달 상태 |
| `CANCELED` | 취소된 자동입찰 |

### 2.2 상한가 · 가격 결정

| 항목 | 정책 |
| --- | --- |
| 등록 상한가의 하한 | **현재가 + 5,000원 이상** |
| 입력 상한가의 단위 | 5,000원 배수일 필요 없음 |
| 실제 사용 상한 `effectiveCap` | 입력 상한 이하에서 가장 가까운 입찰 단위 지점 |
| 동률 우선순위 | 금액이 같으면 **먼저 등록한 사용자**가 승리 |
| 시작 시 예약자가 1명인 경우 | 최소 한 단계 응찰 |
| `CAP_REACHED`에서 상한을 올린 경우 | 다시 계산해 **이겨야만 `ACTIVE`로 복귀** |
| 이미 최고입찰자인 경우 | 상한을 올려도 스스로 현재 가격을 올리지 않음 |

가격 결정식은 다음과 같습니다.

```text
결정 가격 = max(현재가, min(1위 상한, 2위 상한 + 5,000원))
```

### 2.3 취소 · 참여 중단

일반 자동입찰 취소는 **사용자 제재나 경매 상태와 관계없이 항상 가능**합니다.

단, **구매 에이전트가 관리 중인 경우에는 직접 취소를 막습니다.** 이 경우 구매 목표 취소를 통해 요청해야 합니다. 목표 취소 시 현재 자동입찰이 즉시 중단되는지는 목표 상태에 따라 달라집니다.

## 3. 낙찰 · 결제 · 차순위

### 3.1 종료 후 주문

| 상황 | 처리 |
| --- | --- |
| 낙찰자 있음 | 주문 생성 |
| 낙찰자 없음 | 주문 생성하지 않음 |
| 최초 낙찰 주문의 결제 기한 | **경매 종료 시각 + 24시간** |

### 3.2 차순위 제안

| 항목 | 정책 |
| --- | --- |
| 최초 제안 | 낙찰자가 포기하면 2순위에게 제안 |
| 다음 제안 | 2순위가 거절하면 3순위에게 제안 |
| 후보 범위 | **2순위 · 3순위까지**. 4순위부터는 제외 |
| 제안 수락 기한 | 24시간 이내 |
| 수락 후 결제 기한 | **수락 시각 + 24시간** |

### 3.3 페널티

| 사유 | 페널티 | 입찰 제한 |
| --- | --- | --- |
| 낙찰자 포기 | `FORFEITED` | 없음 |
| 결제 기한 초과 | `PAYMENT_EXPIRED` | **7일** |

입찰 제한 기간은 설정값으로 관리하며, **위반 횟수에 따라 늘어나지 않습니다.**

## 4. 구매 에이전트 · PurchaseGoal

### 4.1 목표 상태

기본 흐름은 `ACTIVE → ENGAGED → FULFILLED`이며, 취소와 만료에 따라 아래 상태로 전환합니다.

| 상태 | 의미 |
| --- | --- |
| `ACTIVE` | 경매 후보 탐색 가능 |
| `ENGAGED` | 경매 1건에 참여 중 |
| `FULFILLED` | 낙찰되어 본인의 주문이 생성됨 |
| `CANCEL_REQUESTED` | 참여 중 취소 요청 접수. 현재 자동입찰은 계속됨 |
| `CANCELLED` | 목표 취소 완료 |
| `EXPIRED` | 목표 만료 |

> 경매·자동입찰의 취소 상태는 `CANCELED`, 구매 목표의 취소 상태는 `CANCELLED`입니다.

### 4.2 생성 조건

| 항목 | 조건 |
| --- | --- |
| 마감 | 미래 시각 |
| 예산 상한 `hardMaxAmount` | 0보다 큼 |
| 최소 상태 등급 | 필수 |
| 사이즈 | 선택 |

### 4.3 취소

| 취소 요청 당시 상태 | 변경 상태 | 현재 참여 처리 |
| --- | --- | --- |
| `ACTIVE` | `CANCELLED` | 즉시 목표 취소 |
| `ENGAGED` | `CANCEL_REQUESTED` | 자동입찰을 유지하고 **경매가 끝날 때까지 입찰 계속** |

> **참여 중 목표를 취소해도 현재 자동입찰은 중단되지 않습니다.**

### 4.4 정기 스캔

| 항목 | 설정 |
| --- | --- |
| 실행 주기 | 5분 |
| 기본 활성화 여부 | 꺼짐 |
| 기본 설정 | `purchase-agent.scan.enabled=false` |

스캔은 반드시 다음 순서로 처리합니다.

1. **만료 처리**
2. **참여 결과 확인**
3. **후보 탐색 · 참여**

#### ① 만료 처리

- 마감이 지난 `ACTIVE` 목표를 `EXPIRED`로 변경합니다.
- `ENGAGED` 목표는 참여한 경매의 결과가 나올 때까지 기다립니다.

#### ② 참여 결과 확인

참여한 경매가 끝나면 다음과 같이 처리합니다.

| 결과 · 조건 | 처리 |
| --- | --- |
| 본인의 주문 생성: 낙찰 | `FULFILLED` |
| 패배 · 목표 마감 전 | `ACTIVE`로 복귀한 뒤 **같은 스캔 회차에 다시 탐색** |
| 패배 · 목표 마감 후 | `EXPIRED` |
| `CANCEL_REQUESTED` 상태에서 패배 | `CANCELLED` |

#### ③ 후보 탐색 · 참여

**A. 기본 필터**

| 구분 | 조건 |
| --- | --- |
| 경매 상태 | `LIVE` 또는 **24시간 안에 시작하는 `SCHEDULED`** |
| 상품 조건 | 모델 또는 브랜드, 최소 등급, 선택한 사이즈 일치 |
| 예산 조건 | 예산 상한 ≥ 다음 최소 입찰가 |
| 시세 조건 | 서버 시세가 존재해야 함 |
| 과거 참여 제외 | 본인이 이미 자동입찰을 걸었던 경매는 제외. **취소한 이력도 포함** |

**B. AI 적합도 판정**

- 결과를 **목표 · 경매 조합 단위**로 저장하여 같은 조합에 다시 묻지 않습니다.
- 판정이 실패하면 **폴백 없이 해당 후보만 이번 회차에서 제외**합니다.

**C. 참여 상한 계산**

```text
cap = min(예산 상한, 서버 시세 × 1.0)
```

- 판매자가 입력한 추천가는 사용하지 않습니다.
- **참여 직전에 서버 시세를 다시 확인하여 상한을 다시 계산**합니다.

**D. 후보 순위 결정**

다음 우선순위로 정렬해 **상위 1건**에 참여합니다.

1. 할인율이 큰 순
2. 종료 시각이 빠른 순
3. 적합도 점수 순
4. 경매 ID 순

**E. 참여 확정**

- 목표를 `ACTIVE → ENGAGED`로 바꾸는 **조건부 UPDATE**와 **자동입찰 등록**을 하나의 트랜잭션으로 묶습니다.
- 하나라도 실패하면 **둘 다 롤백**합니다.
- 목표 하나는 `currentAuctionId`를 통해 **동시에 경매 1건에만 참여**합니다.

### 4.5 에이전트 관리 중 사용자 조작

| 동작 | 허용 여부 |
| --- | --- |
| 해당 경매에 직접 입찰 | 불가 |
| 해당 자동입찰 수정 | 불가 |
| 해당 자동입찰 직접 취소 | 불가 |
| 구매 목표 취소 | 가능. `ACTIVE`와 `ENGAGED`의 취소 정책에 따라 처리 |

## 5. 미검증 리스크 · 운영 확인

### 5.1 에이전트 참여와 직접 입찰의 동시 실행

`AgentManagedAuctionGuard`는 잠금 없이 상태를 읽으며, 코드 주석에도 **“재검토 필요”**라고 적혀 있습니다.

에이전트 참여 트랜잭션과 사용자의 직접 입찰이 동시에 실행될 때 가드가 통과할 수 있는지는 **아직 테스트로 검증하지 않았습니다.** 실제 오류가 확인된 상태는 아닙니다.

### 5.2 스케줄러 활성화

다음 스케줄러는 **모두 기본값이 꺼짐**입니다. 운영 또는 시연 환경에서 활성화했는지 확인해야 합니다.

| 스케줄러 | 역할 | 확인할 내용 |
| --- | --- | --- |
| 구매 에이전트 스캔 | 목표 만료 · 결과 확인 · 탐색 · 참여 | `purchase-agent.scan.enabled` 활성화 여부 |
| 결제 만료 | 결제 기한 초과 처리 | 해당 스케줄러 활성화 여부 |
| 차순위 제안 만료 | 수락 기한이 지난 제안 처리 | 해당 스케줄러 활성화 여부 |

### 5.3 검토 범위

- 근거: 실제 구현을 읽고 정리한 코드 검토 내용.
- 테스트: 코드 검토 단계에서 실행하지 않음.
- 이번 문서 편집: 제공된 정책의 구조 · 표현 · 표 정리. 추가 코드 조회나 테스트는 수행하지 않음.
